# Mission Repair Report: rescue_athens

## Problem
In the `rescue_athens` mission, vehicles were not receiving swimmer alerts from the shoreside community.

## Investigation
Upon inspecting the configuration files (`meta_shoreside.moos` and generated `targ_shoreside.moos`), it was discovered that the shoreside community publishes swimmer alerts using vehicle-specific MOOS variables (e.g., `SWIMMER_ALERT_ABE`, `SWIMMER_ALERT_BEN`). 

The `uFldShoreBroker` in `meta_shoreside.moos` was only configured to bridge the generic `SWIMMER_ALERT` variable, which was not being published, causing a breakdown in communication to the vehicles.

## Resolution
Modified `missions/lab_09/rescue_athens/meta_shoreside.moos` to bridge the vehicle-specific swimmer alerts to the generic `SWIMMER_ALERT` variable expected by the vehicles.

### Changes:
- Updated `uFldShoreBroker` block in `meta_shoreside.moos`:
  - Removed generic `SWIMMER_ALERT` from `qbridge`.
  - Added specific bridges:
    ```moos
    bridge  = src=SWIMMER_ALERT_ABE, alias=SWIMMER_ALERT
    bridge  = src=SWIMMER_ALERT_BEN, alias=SWIMMER_ALERT
    ```

## Verification
1.  Regenerated the mission target files using:
    `./launch.sh --just_make --nogui`
2.  Verified that `targ_shoreside.moos` now correctly contains the updated bridge configuration for `SWIMMER_ALERT_ABE` and `SWIMMER_ALERT_BEN`.
